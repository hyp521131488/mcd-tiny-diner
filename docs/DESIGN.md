# 交互与安全设计

## 一、整体流程

```
家长发起
   │
   ├─ 模式A 指一下（照片+指认）
   ├─ 模式B 学声音（拟声词）
   └─ 模式C 今天心情（开心/累了/闹脾气）
   │
   ▼
【MCP 只读阶段】
   now-time-info → query-nearby-stores → query-meals
   → query-meal-detail → list-nutrition-foods
   → query-store-coupons / available-coupons → calculate-price
   │
   ▼
【对孩子】描述（颜色/形状/声音/触感）+ 二元确认
   │
   ▼
【Why-Why 小人之问】最多 3 轮，每轮一个生活化问题
   │
   ▼
【家长卡】价格 + 营养 + 2岁提示 + 合规小字
   │
   ▼   ← 强制人工闸门（家长显式回"确认"）
【MCP 写操作】create-order → query-order
```

## 二、安全设计的四道闸门

| 闸门 | 位置 | 作用 |
|---|---|---|
| 闸门一 · 只读优先 | 全部选品过程 | 未确认前只调用只读工具，杜绝误下单 |
| 闸门二 · 二元限制 | 孩子做选择的每一处 | 从源头降低选择错误与情绪崩溃 |
| 闸门三 · 家长卡 | `calculate-price` 之后 | 价格、营养、风险一次性透明 |
| 闸门四 · 显式确认 | `create-order` 之前 | 必须家长本人回"确认"，孩子点头无效 |

## 三、硬约束清单（不因偏好放松）

- **高钠**：每 100g 钠 > 500mg 的餐品，主动提示"少吃一点"
- **噎食风险**：硬质、圆形、大块食物 → 提示切小段 / 切小块
- **液体**：冰饮、气泡饮对 2 岁不友好 → 温和转向牛奶等
- **过敏**：不主动区分过敏原（避免误判），统一提示"过敏原请家长自行核对并遵医嘱"

## 四、隐私与数据

- 不采集幼儿的姓名、生日、照片等个人信息
- 照片仅用于当次识别，不落盘、不上传至第三方
- `order-list` 的记忆能力需家长同意后才启用
- 仓库内不含任何真实 Token 或凭证，配置文件仅用环境变量占位符

## 五、降级策略

| 故障 | 降级行为 |
|---|---|
| MCP 401 | 提示家长重新激活 Token，暂停流程 |
| MCP 429 | 指数退避；超过阈值则改用静态"最安全两项"兜底 |
| 视觉识别失败 | 请家长重拍，或直接口头报餐品名 |
| 营养数据缺失 | 不臆造数值，标注"该餐品暂无营养数据"，由家长自主判断 |
